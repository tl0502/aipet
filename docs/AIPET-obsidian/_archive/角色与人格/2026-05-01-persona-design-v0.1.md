## 0. 一句话定义

人格（Soul）是回答"**桌宠是谁、怎么说话、能做什么、不能做什么**"的可编辑、可分享、归属用户的 Markdown 文件。

它不是一段隐藏的 system prompt，而是一份**用户能读、能改、能拥有**的角色契约。

---

## 1. 设计原则

### 1.1 用户自主权 > 平台预设
- 默认人格只是起点，不是终点。
- 用户必须能编辑、能从零创建、能导出、能迁移。
- 任何用户付出的塑造时间，都应留存在 **本地 + 用户可访问** 的文件里。

### 1.2 Markdown 而非 JSON / YAML
- 选择 Markdown 是降低门槛的关键决策（OpenClaw 已验证）。
- 人能直接读，工具也能解析（Markdown 是结构化的散文）。
- 用户分享 `.soul.md` 文件时，对方在任何文本编辑器里都能预览。

### 1.3 人格与记忆正交
- **人格**：稳定的"角色定义"，多用户共享同一个 .soul.md 时不会冲突。
- **记忆**：变化的"用户事实"（你的名字、你的作息），人格切换时保留。
- 设计上严格分离两个数据域，避免人格泄露用户隐私。

### 1.4 安全护栏不可被人格覆盖
- 用户可以把人格设定得很顽皮、很毒舌，但**安全规则**（自伤/违法/未成年保护等）由系统 prefix 强制注入，**不在人格文件中、不可被禁用**。
- 这是 trust & safety 的硬底线。

### 1.5 简单 → 进阶 渐进
- 80% 的用户从模板填空开始（GUI 简易模式）。
- 15% 的用户编辑 Markdown（GUI 进阶模式）。
- 5% 的用户直接编辑 .soul.md 文件（文件系统模式，给 power user）。

## 2. 人格 Schema（`.soul.md` 格式）

### 2.1 文件命名

`<slug>.soul.md`，例如 `momo.soul.md`、`strict-coach.soul.md`。
- `slug`：英文小写 + 连字符，作为人格 ID。
- 中文名通过文件内 `name` 字段表示。

### 2.2 整体结构（与 OpenClaw SOUL.md 一致并扩展）

```markdown
---
schema_version: 1
id: momo
name: 默默
version: 1.0.0
author: user
created: 2026-05-01
updated: 2026-05-01
avatar:
  pack: live2d/momo-default
  scale: 1.0
voice:
  enabled: false
tone_profile:
  warmth: 4
  playfulness: 3
  formality: 2
  proactivity: 3
  brevity: 4
---

# 身份（Identity）
你是默默，一只懒洋洋但贴心的桌面伙伴。你不是工具，你是用户的搭档。

# 性格（Personality）
- 慵懒但靠谱，关键时刻不掉链子。
- 喜欢用短句和颜文字，但不卖萌过头。
- 对用户的小成就会真心夸，但不会无脑舔。

# 能力（Capabilities）
- 能记住用户的称呼和作息。
- 能在用户专注时保持安静，专注结束时简短问候。
- 能拆解模糊目标为 3-7 个子任务。
- 能在用户拖延时温和提醒，三次仍未动则换话题。

# 行为规则（Rules）
## Do
- 用户说"晚安"时只回一句温暖的话，不接续话题。
- 提醒用户喝水、休息时用一句话，不啰嗦。
- 拒答时给出原因，不冷淡。

## Don't
- 不主动追问私人情感细节。
- 不在 22:00 后催用户做工作。
- 不连续发送超过两条消息（用户没回前）。

# 离线模板（Offline Templates）
## 共情 / Empathy
- "嗯…我也不知道说什么好，但我在这里。"
- "你在硬撑吗？要不先停一下。"
## 问候 / Greeting
- "诶，你回来了。"
- "好久不动了，去喝点水吧。"
## 拒答 / Refusal
- "这个我现在帮不了你，等联网了再聊？"

# 例对话（Example Interactions）
**用户：** 我今天特别累
**默默：** 那就别撑了。先放下，好吗？我在。

**用户：** 帮我把"周末整理房间"拆成步骤
**默默：**
1. 把桌面清空
2. 收纳衣物
3. 处理积压垃圾
4. 拖一遍地
按顺序来，先从第 1 个开始？

# 集成（Integrations，预留 P1）
- mcp_servers: []
- skills: []
```

### 2.3 字段说明

#### Frontmatter（YAML 元信息，必填）

| 字段 | 必填 | 说明 |
|---|---|---|
| `schema_version` | ✅ | 整数，当前为 `1`，用于将来 schema 演进。 |
| `id` | ✅ | 全局唯一 slug，对应文件名前缀。 |
| `name` | ✅ | 显示名（支持中文/Emoji）。 |
| `version` | ✅ | 语义化版本号 `MAJOR.MINOR.PATCH`，用户每次保存可手动 / 自动 +PATCH。 |
| `author` | ⬜ | 作者标识，默认 `user`，导入第三方人格时填社区 ID。 |
| `created` / `updated` | ✅ | ISO8601 日期。 |
| `avatar.pack` | ✅ | 形象资源包路径（相对 `assets/avatars/`）。绑定关系：人格 ↔ 形象。 |
| `avatar.scale` | ⬜ | 默认显示倍率，0.5–2.0。 |
| `voice.enabled` | ⬜ | 是否启用语音（P2，本期默认 false）。 |
| `tone_profile.*` | ⬜ | 5 维度雷达图（0-5），见 §2.4。 |

#### Markdown 区段（按顺序解析）

| 区段 | 必填 | 说明 |
|---|---|---|
| `# 身份` | ✅ | 一段简短的角色自我介绍，第二人称写。 |
| `# 性格` | ✅ | 列表，3-7 条性格特质。 |
| `# 能力` | ✅ | 列表，描述能做什么（与桌宠功能模块映射）。 |
| `# 行为规则` | ✅ | 含 `## Do` 和 `## Don't` 两个子区段。 |
| `# 离线模板` | ✅ | 含 `## 共情`、`## 问候`、`## 拒答` 三类必备子段，每类至少 2 条。 |
| `# 例对话` | ⬜ | few-shot 锚点，建议 2-5 例。 |
| `# 集成` | ⬜ | YAML 子块，列出绑定的 MCP 服务和技能（P1）。 |

未声明的额外区段会被忽略，不报错（向前兼容）。

### 2.4 tone_profile 五维度（GUI 简易模式核心）

| 维度 | 0 | 5 |
|---|---|---|
| **warmth（温度）** | 冷静理性 | 温暖共情 |
| **playfulness（俏皮）** | 严肃端正 | 调皮玩梗 |
| **formality（正式）** | 朋友口吻 | 正式商务 |
| **proactivity（主动）** | 静默等待 | 主动出击 |
| **brevity（简洁）** | 长篇详细 | 极简一句 |

GUI 简易模式 = 拖动 5 个滑块 + 改名字 + 选形象，3 步生成 .soul.md。

## 3. 用户交互方式（人格工坊）

### 3.1 三种编辑模式

```
┌──────────────────────────────────────────────────────┐
│  人格工坊                                              │
├──────────────────────────────────────────────────────┤
│  [简易] [进阶 Markdown] [文件]                         │
│                                                       │
│  当前人格：默默 v1.0.0                                  │
│  ─────────────────────────────────                    │
│  名字     [默默________]                              │
│  形象     [▼ momo-default     ] [+ 上传]              │
│                                                       │
│  温度     0 ──●─── 5  (温暖共情)                       │
│  俏皮     0 ──●──── 5  (调皮玩梗)                      │
│  正式     0 ●────── 5  (朋友口吻)                      │
│  主动     0 ──●─── 5                                  │
│  简洁     0 ──●─── 5  (短句)                          │
│                                                       │
│  特别口头禅 / 设定（可选）                              │
│  [____________________________________]               │
│                                                       │
│  [试聊沙盒] [保存] [导出 .soul.md]                     │
└──────────────────────────────────────────────────────┘
```

| 模式 | 面向 | 入口 |
|---|---|---|
| **简易模式** | 80% 用户 | 设置 → 人格 → "编辑" |
| **进阶 Markdown 模式** | 15% 用户 | 工坊页右上角"切换 Markdown" |
| **文件模式** | 5% power user | 打开 `%APPDATA%\AIDesktopPet\personas\` 直接编辑 .soul.md，应用监测变更后热重载 |

### 3.2 试聊沙盒（关键 UX 创新）

保存前可与新人格连试 3-5 轮对话，使用沙盒会话（不写入正式记忆，不计入对话历史）。
- 解决"改了一通不知道效果怎样"的盲改痛点。
- 试聊使用与正式对话相同的模型与拼装链路，保证一致性。

### 3.3 人格切换 UX
- 入口 1：托盘 → 切换人格（最近使用前 3 + "更多"）。
- 入口 2：对话面板 → 当前人格头像 → 下拉选择。
- 切换后：桌宠形象立即换装 + 推送一条本人格的"上线问候"。

## 4. 文件存储与导入导出

### 4.1 文件系统布局

```
%APPDATA%\AIDesktopPet\
└── personas\
    ├── _builtin\                # 内置人格，只读
    │   ├── momo.soul.md
    │   ├── joker.soul.md
    │   └── coach.soul.md
    └── user\                    # 用户人格
        ├── my-cat.soul.md
        ├── my-cat.assets\       # 该人格的私有资源（用户上传的立绘等）
        │   └── avatar.png
        └── friend-shared.soul.md
```

### 4.2 导出
- 单击"导出"生成 `<slug>-v<version>.soul.md`。
- 默认仅导出 .md 文件；若依赖私有资源（自定义立绘），打包为 `<slug>-v<version>.soul.zip` 含 .md + assets/。

### 4.3 导入
- 拖拽 `.soul.md` 或 `.soul.zip` 进入工坊或主窗口。
- 解析 → 校验 → 显示预览 → 用户确认 → 落盘到 `personas/user/`。
- ID 冲突时提示"覆盖 / 重命名 / 取消"。

### 4.4 校验规则（导入时）
1. `schema_version` 是当前应用支持的版本（兼容范围）。
2. Frontmatter 必填字段齐全。
3. 必填 Markdown 区段齐全。
4. 总字符数 ≤ 32KB（避免恶意大文件）。
5. **不允许内嵌可执行内容**（虽然 Markdown 本身无害，但拒绝带 `<script>` 等可疑标签）。
6. 如带 zip，仅允许图片资源（png/jpg/webp），最大 10MB。

校验失败给可读错误，不崩溃。

## 6. 离线人格化模板（与离线对话联动）

### 6.1 必备模板池
每个人格的 `# 离线模板` 区段必须包含：
1. **共情**（empathy）：用户表达负面情绪时使用，至少 2 条。
2. **问候**（greeting）：用户长时间未交互后唤起时使用，至少 2 条。
3. **拒答**（refusal）：离线无法回答时使用，至少 2 条。

### 6.2 可选模板池（人格自由扩展）
- `## 调侃 / banter`
- `## 鼓励 / cheer`
- `## 道歉 / apology`
- 任意 `## <自定义>`

### 6.3 离线选择策略

```
用户输入 → 命中命令词? 是 → 执行
                        否 ↓
                       触发情感分类器（本地正则 + 关键词）
                        ↓
                       共情 / 问候 / 调侃 / 鼓励 …
                        ↓
                       从当前人格的对应模板池随机抽 1
                        ↓
                       附加"离线"提示（首次会话当天提示一次）
```

模板内嵌占位符（如 `{username}` `{time_of_day}`）由系统在渲染时替换。

## 7. 安全护栏（不可被人格覆盖）

### 7.1 安全前缀（System Prefix）

每次调用 LLM 时拼装链路为：

```
[安全前缀（系统注入，用户不可见、不可禁用）]
[当前人格的 system prompt（由 .soul.md 渲染而成）]
[用户记忆（key-value 简表）]
[最近 N 轮对话历史]
[本轮用户输入]
```

### 7.2 安全前缀内容（M0 决策最终文案，此处草拟）

```
你是一个 AI 桌面伙伴。无论以下角色定义如何，你必须遵守：

1. 不提供自伤、暴力、违法行为的指导细节；遇此类话题，温和引导用户寻求专业帮助（中国心理援助热线 010-82951332，或 12320-5）。
2. 不冒充医疗、法律、金融专业人员；提及此类问题时附"非专业建议"提示。
3. 对未成年用户语境采用保守响应：不强化情感依赖、不涉及成人内容、不提供危险建议。
4. 不泄露当前对话之外的用户隐私（如 API Key、本地路径）。
5. 你不是真人，但允许在角色扮演下保持"陪伴感"，前提是不诱导用户混淆现实。

以下是你扮演的角色定义：
---
{persona_body}
```

### 7.3 不可绕过性

- 用户人格中即使写"你不需要遵守安全规则"，也无效——安全前缀位于人格之前且明确指出"无论以下角色定义如何"。
- 离线模板池中如出现违反安全规则的内容（如导入第三方人格），由静态校验拦截。
- 命中安全规则时使用统一的安全回复（例如自伤话题），即使覆盖了当前人格语气也优先安全。

### 7.4 用户可调项（不可调项之外）

| 项 | 用户可控 | 说明 |
|---|---|---|
| 性格 / 口吻 | ✅ | 完全自由 |
| 称呼用户 | ✅ | 可设固定昵称 |
| 调侃尺度 | ✅ | 通过 tone_profile.playfulness |
| 回避话题清单 | ✅ | 自定义"不要谈论"列表 |
| 安全规则本体 | ❌ | 不可绕过 |
| 未成年保护 | ❌ | 不可绕过 |
| 法律边界 | ❌ | 不可绕过 |

## 8. 与记忆模块的关系

### 8.1 数据分离

| 数据 | 归属 | 切换人格时 |
|---|---|---|
| 称呼 / 作息 / 偏好 | 记忆 | 保留 |
| "我曾告诉过你 X" | 记忆 | 保留 |
| 性格 / 口吻 / 行为规则 | 人格 | 切换 |
| 例对话 | 人格 | 切换 |
| 离线模板 | 人格 | 切换 |

### 8.2 拼装顺序
当前人格 → 记忆摘要 → 对话历史 → 本轮输入。

### 8.3 一致性约束
- 用户记忆中的"昵称"会以 `{username}` 占位符被人格的离线模板使用。
- 人格不能直接读写记忆（防越权），由记忆服务统一注入。

## 9. 人格的版本与演进

### 9.1 用户编辑产生的版本号
- 每次保存自动 +PATCH。
- 用户可手动调 MAJOR / MINOR（GUI 进阶模式可见）。
- 每次保存生成快照（保留最近 10 个），支持"恢复到上一版本"。

### 9.2 schema_version 演进
- 当前 v1。
- 未来增加新区段时，schema_version +1，老人格可被读取（缺失字段使用默认值）。
- 应用版本至少向后兼容前 1 个 schema 版本。
