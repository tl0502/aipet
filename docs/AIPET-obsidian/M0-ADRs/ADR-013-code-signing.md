# ADR-013: 签名分发(EV 证书与发布渠道)

- **状态**: Accepted
- **决策日期**: 2026-05-01
- **Owner**: M0 决策周(产品 + 运维)
- **Reviewers**: M0 决策周复审通过
- **目标完成**: M0 决策周已确认 M5 灰度策略;EV/OV 评估推到 M5+ 公开发布期
- **影响范围**: 自动更新 / 用户首启信任 / Windows SmartScreen 警告

## 背景

PRD v0.6 §15 决策项 #5 提到:**是否购买 EV 代码签名证书**。这影响:
- Windows SmartScreen 在用户运行时是否弹"未知发布者"红条
- 自动更新(tauri-updater)的签名校验
- 灰度内测期用户安装率

不签名 → 红条警告 → 大量用户放弃安装。
签名 → 信任建立但成本上升。

## 备选方案

### 选项 A:**EV 代码签名证书(Extended Validation,推荐发布期)**

向 DigiCert / Sectigo / GlobalSign 等 CA 申请 EV 证书。

**优点**
- **首次安装就建立 SmartScreen 信誉**(无需积累用户信誉时间)
- 显示"已知发布者"绿条
- 满足 Windows 生态最严信任要求

**缺点**
- **成本高**:$300-500/年
- 申请流程复杂(需要营业执照 / 法人验证 / 物理 USB token 寄送)
- 需要法人主体(个人开发者门槛高)

### 选项 B:**OV 代码签名证书(Organization Validation)**

普通组织验证证书。

**优点**
- 成本较低($100-200/年)
- 申请流程简单

**缺点**
- **需要积累 SmartScreen 信誉**(最初一段时间仍然弹红条)
- 通常需要数千次安装 + 数月才能建立信誉

### 选项 C:**不签名 + 用户教育**

直接发布,在下载页明确告知用户"会出现红条警告,这是正常的"。

**优点**
- 零成本

**缺点**
- 用户流失率极高(~50% 看到红条直接关闭)
- 不适合任何严肃产品

### 选项 D:**Microsoft Store 上架**

通过 Microsoft Store 分发,Microsoft 会做签名 + 信任建立。

**优点**
- 用户信任度最高
- 自动更新由 Store 处理

**缺点**
- 上架审核流程长(数周到数月)
- 30% 平台抽成(若 P2-R3 商店上线)
- Tauri 应用上架 Store 需要做 MSIX 打包,工作量增加
- 失去自主发布灵活性

## 我的倾向

**M5 灰度期使用选项 B(OV 证书),公开发布期升级到选项 A(EV 证书)**:

### 阶段 1:M5 灰度内测(W9-W10)
- 申请 OV 证书(成本低,审批快)
- 内测用户数量小,SmartScreen 信誉积累压力低
- 用户教育 + 在内测页明确告知

### 阶段 2:公开发布(M5+)
- 升级到 EV 证书
- 同步评估 Microsoft Store 上架(可作为额外渠道,但不替代直接下载)

### 阶段 3:P1-R1 后(可选)
- 评估 Mac 签名(若启动 macOS 平台)

## 决策

**选定:选项 C — 不签名 + user education**(M5 灰度期)。EV/OV 证书与 Microsoft Store 上架推到 **M5+ 公开发布期**,基于内测真实流失率数据决策。

下载页明确告知"会出现 SmartScreen 警告,这是正常的",同步引导用户点击"仍要运行"。内测群直接发分发链接 + 教育文案,降低初次接触流失。

**对比"我的倾向"段(M5 OV / 公开发布期 EV)的调整**:M0 决策周讨论后选 C 而非 B,理由:① M5 仅约 100 名内测用户(灰度第 2 周扩到 100),签名成本对内测规模不必要 ② 用户教育 + 内测群引导可有效减轻流失 ③ EV/OV 评估推到 M5+ 由真实数据驱动决策(看用户流失率与签名 ROI)。

## 后果

### 正面
- M5 灰度零成本上线,不阻塞内测节奏。
- 决策可逆:M5+ 真实数据驱动 EV/OV 选择(若内测流失 > 30% 立即升级 OV)。
- 内测群直接分发,user education 文案到位时流失可控。

### 负面
- 公开发布期(M5+)前必须有签名方案,否则面向陌生用户安装率受重创(行业经验 ~50% 流失)。
- 用户教育文档需要在下载页 / 内测群 / 自动更新公告三处同步,任何环节漏掉都会放大流失。
