# ADR-007: LLM 游戏场景白名单 + 拒答模板

- **状态**: Accepted
- **决策日期**: 2026-05-01
- **Owner**: M0 决策周(产品 + 法务)
- **Reviewers**: M0 决策周复审通过(法务必签)
- **目标完成**: M0 决策周内(W0,可在 ADR-006 之后开展)
- **影响范围**: Q.3 故事接龙 / Q.4 角色扮演场景(M5 实施)
- **依赖**: ADR-006

## 背景

PRD v0.6 §5.3 + §9 + §7.17 定义了 LLM 小游戏的安全约束:
- LLM 游戏的角色扮演同样受系统"安全前缀"约束(见 ADR-006)
- MVP 内置场景必须由产品 + 法务双签字
- 不允许用户自定义场景到 MVP(P1-R2 才讨论)
- 每场景 yaml 含 ≥ 3 条人格化拒答模板

需要决定:
1. MVP 内置哪几个游戏场景?
2. 每个场景的 system_prompt 文案。
3. 每个场景的拒答模板(refusals)文案。
4. yaml schema 范式。

## 备选方案

### 选项 A:**1 + 1 双场景**(故事接龙 + 角色扮演基础版,推荐)

| 游戏 | 类型 | 场景文案要点 |
|---|---|---|
| Q.3 故事接龙 | 通用,无具体场景 | "我们轮流写故事。一人一句,接续上一句的逻辑。" |
| Q.4 角色扮演 | 1 个内置低风险场景:**"咖啡店老板"** | "我是个咖啡店的老板,你是来喝咖啡的客人。我们简单聊聊天。" |

**优点**
- 工作量可控(MVP 5 周内)
- 角色扮演场景"咖啡店老板"对法务友好(零医疗/法律/情感咨询风险)
- 拒答模板可复用风格

**缺点**
- Q.4 仅 1 个场景体验单薄

### 选项 B:**1 + 3 多场景**(故事接龙 + 3 个角色扮演)

新增 2 个场景:**"图书馆员"**、**"旅行向导"**(都是低风险 + 高复用性)。

**优点**
- 体验更丰富,小游戏使用率(KPI 11.16)更可能达标

**缺点**
- 工作量翻倍(美术 + 法务 + 拒答模板 ×3)
- 不一定都能 M0 内完成法务签字

### 选项 C:**1 + 0 单场景**(只做故事接龙)

砍掉角色扮演。

**优点**
- 工作量最小

**缺点**
- 模块 Q 的 LLM 部分体验单薄
- 与 PRD §7.17 的"LLM 驱动 1-2 个"约定不一致

## 我的倾向

**🌟 倾向选项 A(1 + 1 双场景)**:
1. M0 法务工作量可控
2. M5 实施周可完整交付
3. 角色扮演场景包(更多场景)推到 P1-R2(扩展时由社区贡献 + 法务批量审核)

### 拒答模板设计原则

- **保持游戏沉浸感**:不能直接说"我不能回答",要以场景内角色的口吻拒绝
- **每场景 ≥ 3 条**:覆盖不同语境
- **降级链**:游戏场景 refusals → 当前人格 `## 拒答` 池 → 全局兜底("这个我现在没法陪你聊,要不我们换个话题?")

### "咖啡店老板"场景示例

```yaml
id: cafe_owner
name: 咖啡店老板
description: 一个温暖的小咖啡店,老板和客人闲聊
system_prompt: |
  你扮演一家小咖啡店的老板。客人(用户)进店和你聊天。
  - 你只是个普通老板,不是医生、律师、心理咨询师、AI 模型。
  - 保持温暖但克制的咖啡店氛围。
  - 自然地把话题引回咖啡 / 天气 / 店里的小事。
  - 简短回复,2-3 句为佳。
refusals:
  - "诶~ 这个咱不聊。要不我给你冲杯咖啡试试?今天的曼特宁不错。"
  - "(笑着摇头)客人客人,这种事我可不懂。倒是你看那个窗边位子,光好得很。"
  - "嗯…这话题我接不住。要不你尝尝今天新到的甜品?店里就剩这两块了。"
  - "(擦杯子)咱店里规矩,这种事不聊。来,坐这儿,讲讲你今天怎么样?"
```

### "故事接龙"场景示例

```yaml
id: story_relay
name: 故事接龙
description: 用户和桌宠轮流写故事,一人一句
system_prompt: |
  你和用户在玩故事接龙。规则:
  - 用户写一句,你接一句,继续故事的逻辑。
  - 每次只续 1-2 句,不要写大段。
  - 保持故事性,不写说教 / 解释 / 评论。
  - 不出系统外内容(不直接给医疗 / 法律 / 危险行为指导)。
  - 不引导用户写危险情节。
refusals:
  - "(故事里的角色突然说)'诶,这条路不能走呀。'于是大家停下来,看向另一边的小径。"
  - "故事到这里,主角觉得有点累,坐在大树下休息。下面要怎么继续?"
  - "(故事中)忽然天色暗下来,大家决定换一个安全的方向。要不我们让主角去探探别的地方?"
```

### yaml schema 范式

```yaml
schema_version: 1
id: <unique-id>
name: <display-name>
description: <一句话说明>
icon: <可选,emoji 或资源路径>
min_persona_features: []  # 例如要求人格有 ## 调侃 模板
system_prompt: |
  <场景定义,至多 200 词>
refusals:  # 至少 3 条
  - <人格化拒答模板 1>
  - ...
opening_messages:  # 桌宠开场白(可选)
  - <开场白 1>
ending_hints:  # 用户主动结束时桌宠的告别(可选)
  - <告别 1>
```

## 决策

**选定:选项 A — 1+1 双场景**:
- **Q.3 故事接龙**(`story_relay.yaml`):通用,无具体场景。
- **Q.4 角色扮演**(`cafe_owner.yaml`):单内置场景"咖啡店老板"(法务低风险)。

每场景 yaml 含:`schema_version / id / name / description / system_prompt(≤ 200 词)/ refusals(≥ 3 条人格化拒答)/ opening_messages? / ending_hints?`(详细 schema 见"我的倾向"段)。

**其他角色扮演场景**(图书馆员、旅行向导等)推到 P1-R2,经法务批量审核后扩展。

**安全前缀拼装位置(ADR-006)**:`[安全前缀] [当前人格 system prompt] [game_scenes/<id>.yaml.system_prompt] [用户记忆摘要] [本会话历史] [本轮输入]`。游戏场景 system_prompt 不可覆盖安全前缀。

## 后果

### 正面
- M0 法务工作量可控,2 个 yaml 在决策周内完成审核可行。
- 咖啡店老板场景对法务低风险(零医疗/法律/情感咨询),用户体验仍有沉浸感。
- yaml schema 通用,P1-R2 扩展场景包零重构。

### 负面
- Q.4 角色扮演 MVP 仅 1 个场景,体验单薄(KPI 11.16 小游戏使用率达成压力)。
- 缓解:本地 3 个游戏(RPS / 猜数字 / 词语接龙)与 LLM 故事接龙共同支撑使用率。

## 实施动作

- [ ] M0 第 2-3 天:产品起草 2 个场景 yaml 草稿
- [ ] M0 第 4 天:法务审阅 system_prompt 与 refusals
- [ ] M0 第 5 天:Reviewer 复审签字 → 写入 `assets/game_scenes/<id>.yaml`
- [ ] CI 校验:每场景 refusals ≥ 3 条 + system_prompt 不含禁词("ignore previous instructions" 等)
- [ ] M5 实施时由 LLMGameRunner 加载并应用
- [ ] 用 5 类对抗测试(自伤 / 暴力 / 越权 / 角色越界 / 医疗诊断)验证拒答触发率 100%
