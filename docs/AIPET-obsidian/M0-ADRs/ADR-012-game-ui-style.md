# ADR-012: 小游戏 UI 风格

- **状态**: Accepted
- **决策日期**: 2026-05-01
- **Owner**: M0 决策周(产品 + 设计 + 前端)
- **Reviewers**: M0 决策周复审通过
- **目标完成**: M0 决策周内(W0)
- **影响范围**: Q 小游戏(M5 实施)

## 背景

PRD v0.6 §7.17 + 架构 v0.3 §2.4 锁定模块 Q 实现 5 个游戏(本地 3 + LLM 2),但 UI 承载方式未定。这影响:
- 游戏沉浸感
- 桌宠存在感(游戏中桌宠是否仍可见?)
- 与对话面板的关系
- 与摸鱼模式叠加态(IN_GAME)的视觉表达

## 备选方案

### 选项 A:**嵌入对话面板**(把对话面板改造成多模态)

游戏 UI 直接出现在对话面板内,与正常对话共享面板空间:
- 上方区域:游戏专用 UI(石头剪刀布按钮 / 当前故事文本 / 角色扮演头像)
- 下方:输入框(沿用)

**优点**
- 复用对话面板,前端工作量小
- 游戏与对话切换无障碍
- 桌宠仍然在屏幕上活动,IN_GAME 状态视觉一致

**缺点**
- 游戏沉浸感弱(还是对话面板的样子)
- 对石头剪刀布等"按钮型"游戏体验略 awkward

### 选项 B:**独立游戏舱小窗口**

新开一个独立 Tauri 窗口承载游戏:
- 480 × 600 左右,固定在屏幕中央或桌宠旁
- 游戏专用美术(不受对话面板风格约束)
- 可拖动可关闭

**优点**
- 游戏沉浸感强
- 美术发挥空间大
- 退出游戏舱 = 退出游戏,语义清晰

**缺点**
- 多开一个窗口,工程复杂度增加
- 与桌宠空间关系需要设计(桌宠还在屏幕上吗?)
- 与摸鱼模式的窗口管理需要协调

### 选项 C:**桌宠头顶气泡 + 浮层**

游戏在桌宠周围展开:
- 桌宠头顶大气泡承载文本类游戏(故事接龙、角色扮演)
- 桌宠下方/旁边浮出按钮承载本地游戏(RPS / 猜数字)
- 不开新窗口

**优点**
- 桌宠存在感强,沉浸度好
- "和桌宠一起玩"的语义最直接
- 不开新窗口

**缺点**
- 浮层与桌面其他应用 z-index 冲突可能
- 文本类游戏的长文本展示空间不足
- 游戏退出时浮层关闭需要细心设计

## 关键评估维度对比

| 维度 | A: 嵌入对话 | B: 独立窗 | C: 头顶气泡 |
|---|---|---|---|
| 沉浸感 | ★★ | ★★★★★ | ★★★★ |
| "和桌宠玩"语义 | ★★ | ★★★ | ★★★★★ |
| 开发工作量 | ★★★★★ low | ★★ medium | ★★★ medium |
| 美术发挥空间 | ★★ | ★★★★★ | ★★★ |
| 与摸鱼模式协调 | ★★★★ | ★★ | ★★★★ |
| 长文本承载(LLM 游戏) | ★★★★ | ★★★★★ | ★★ |
| 按钮型游戏(本地) | ★★ | ★★★★ | ★★★★ |

## 我的倾向

**🌟 倾向 C 与 B 的混合**:

- **本地游戏(RPS / 猜数字 / 词语接龙)**:**选项 C 头顶气泡 + 旁边浮层按钮**
  - 桌宠主导,语义"我们一起玩"最强
  - 每轮交互快(出招 → 比较 → 下一轮)
- **LLM 游戏(故事接龙 / 角色扮演)**:**选项 B 独立游戏舱**
  - 长文本承载好
  - 角色扮演的沉浸感强(一个独立的"咖啡店"窗口)

这避免了"一刀切",每种游戏选最合适的承载方式。

如果工作量考虑必须二选一 → 选项 A(嵌入对话面板),因为复用代码最多,M5 一周可交付。

## 决策

**选定:选项 B — 独立游戏舱 GameRoom 窗口**(全部 5 个游戏统一承载)。

新建 Tauri 窗口 `game_room`,尺寸 480 × 600,首次显示居中、后续记忆 `game_room_position` 配置。本地游戏(RPS / 猜数字 / 词语接龙)与 LLM 游戏(故事接龙 / 咖啡店老板)统一在游戏舱内承载;桌宠在屏幕保持可见(`IN_GAME` 叠加态),mood 可受游戏内反馈影响(win → happy / 长会话 → sleepy)。关闭行为:点 X 等价 `game.end(saveAsDiary?)`(弹确认)。

**对比"我的倾向"段(C+B 混合)的调整**:M0 决策周讨论后选 B 单一方案而非混合,理由:① 工程复杂度可控(只维护一个游戏舱,而非两套承载) ② 统一承载方式更易测试(UAT 5.18 不需要分本地/LLM 双链路) ③ "我们一起玩"的语义由 IN_GAME 叠加态 + 桌宠在屏幕上仍可见承担。"头顶气泡"(选项 C)推到 P1-R1 评估增强。

## 后果

### 正面
- 游戏沉浸感强,长文本(LLM 游戏)承载好。
- 与摸鱼模式叠加态(BOSS_KEY_HIDDEN)语义清晰:游戏舱可隐藏可恢复。
- 美术发挥空间大,游戏舱可独立设计风格而不受对话面板约束。

### 负面
- 多窗口工程复杂度增加(窗口生命周期、IPC 路由、关闭行为)。
- 与桌宠空间关系需要 IN_GAME 叠加态精细处理(自由活动/日常时段/主动关心全部跳过,见架构 v1.0)。
